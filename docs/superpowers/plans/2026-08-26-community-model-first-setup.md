# Community Model-first Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the abrupt provider-first Community setup screen with a clear, model-first setup that groups models by vendor and treats OpenRouter as an optional routing choice.

**Architecture:** Keep `ProviderConfig` as the normalized transport and persistence contract, but introduce a model-choice catalog that maps each user-facing model to its OpenRouter ID and optional direct-provider ID. `ProviderSetup` owns only UI state (`selectedModelKey`, `useOpenRouter`, API key, and custom ID) and derives the transport configuration when testing or saving.

**Tech Stack:** React 19, TypeScript 7, WXT 0.21, Vitest 4, Testing Library.

**Spec:** `docs/superpowers/specs/2026-08-26-community-model-capture-reintegration-design.md`

## Global Constraints

- Do not expose a separate Provider field.
- OpenRouter is a checkbox and defaults to enabled.
- Anthropic, Qwen, and custom models require OpenRouter in this version.
- Direct official routing is available only for curated OpenAI and Google models.
- Remove the multimodal acknowledgement checkbox; retain a warning for custom models.
- Keep API keys in extension session storage and do not add Cloud requests.
- Do not change capture behavior in this stage.
- Preserve the approved model list and exclude `gemini-3.1-pro-preview`.

- [ ] **Step 3: Implement the catalog and resolver**

Use these stable shapes:

```ts
export type ModelVendor = 'openai' | 'anthropic' | 'google' | 'qwen';

export type ModelChoice = Readonly<{
  key: string;
  vendor: ModelVendor;
  label: string;
  openRouterModel: string;
  direct?: Readonly<{ provider: Extract<ProviderKind, 'openai' | 'gemini'>; model: string }>;
  description: Readonly<{ en: string; 'zh-CN': string }>;
  badge?: Readonly<{ en: string; 'zh-CN': string }>;
  default: boolean;
}>;

export type ResolvedModel = Readonly<{
  provider: ProviderKind;
  model: string;
  customModel: false;
}>;
```

`resolveModelChoice` uses the direct route only when `useOpenRouter === false` and `choice.direct` exists; otherwise it returns the OpenRouter route. Derive `curatedModels` from these choices so provider validation has one source of truth.
